# PITBULL Stage 6.2 • High-End Drawing Packet

This stage upgrades three visible instruments without cutting analytical methods.

## Fork Instrument

The Pitchfork now behaves as structural geometry rather than a per-bar redraw.

- A/B/C construction is retained.
- Median, upper and lower rails become semi-transparent projected rays.
- Main geometry refreshes only when the structural pivot triplet changes.
- Three short current-level dashes move once per closed bar so the trader can read the fork's live upper / median / lower levels.
- The fork card reports state, upper/median/lower levels, signed ATR distance from the median, and occupancy.

## Wave Change Packet

Wave cards are no longer tied only to `newEpisode`.

A snapshot may publish when:
- a new episode starts, or
- direction / wave state / status materially changes.

Each card carries BODY / SPACE / TIME verbs, FIELD score, density, time confluence, target and nearest active FVG relation.

The history is a recycle ring: after the configured history fills, oldest line/card handles are reused with setters rather than deleted and recreated.

## Position Packet

The existing risk/reward corridor remains.

A persistent active-position card shows Entry, current price, R, MFE, MAE, Stop, Target and RR.

Position trace history uses modulo slots. Once the trace slot count fills, old line handles are reused. This preserves visual history while stopping registry-key growth and repeated prune churn.

## Runtime discipline

Stage 6.1 closed-bar visual latching remains intact. The strategy may calculate intrabar, while these instruments update only on the confirmed-bar visual commit.

## Publication

No library API changed. Reuse the same Stage 6 libraries and compile only the Stage 6.2 master.
